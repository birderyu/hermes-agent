## 发行版

[v0.21.6](https://github.com/NousResearch/hermes-agent/releases/tag/v0.21.6)（2026-10-08）是官方新发布流水线出的第一个版本，标签命名从 `vYYYY.M.D` 改为 `vX.Y.Z`；与 v0.21.5 之间有 8,867 个非合并提交、约 2,100 个 PR，完整说明要等 v0.22.0。预检：`f97608f178` 是标签的祖先，标签可从 `upstream/main` 到达。`rc.*`、`*+canary.*` 标签不是发行版。

和本 fork 相关的变化：

- **安全修复**：dashboard 登录限流可被伪造 `X-Forwarded-For` 绕过等四项；自动 git 调用可能执行不受信仓库配置的 filter 程序；邮件网关发件人校验。这是这次升级的主要理由。
- **依赖改由 `pm` 管理**：工具在 `$HERMES_RUNTIME_DIR`（默认 `~/.hermes/tools`），环境在 `$HERMES_HOME/installs/`；不能再用裸 `pip`/`uv` 改环境。开发环境因此要隔离，见 [维护方式](../maintenance.md#开发环境)。
- **用户语言覆盖层**：`$HERMES_HOME/locales/<语言>.yaml` 可以覆盖内置文案。
- **任务事件流**：`/v1/runs/{id}/events` 改为带序号的 `_RunStream`，支持多订阅、保留最近 1000 个事件、按 `Last-Event-ID` 续传；仍在内存里，进程重启即丢。
- **Photon**：上游已展开 iMessage `reply`、丢弃 `read`/`read_receipt`，并把 sidecar 依赖固定在 `spectrum-ts 12.7.0`。
- 插件默认仍在网关进程内运行（`plugins.isolation: in_process`）；Ollo 插件用到的钩子与接口都还在。

## 补丁取舍

依据个人档案的修订记录和对 v0.21.6 代码的逐项核对：

| 补丁 | 决定 | 理由 |
| --- | --- | --- |
| 会话重置提示本地化 | 移除，改用语言覆盖 | 上游已本地化，只剩「对话历史已清空」措辞不准；原补丁改 17 个语言文件和 `run_turn.py`，每次升级都冲突 |
| iMessage `reply` 解码 | 移除 | 上游 `348a68bb4e` 等价且更完整 |
| 已读回执与重复投票 | 移除 | 上游已丢弃回执；首次投票锁早被纠正 |
| 位置卡片一组 9 个 | 移除 | Photon Cloud 不给位置数据（上游 issue #53 未修），实际只有兜底提示；位置改由 Ollo App 提供；靠改写 Spectrum 依赖代码，维护成本最高 |
| 空投票标题 | 保留 | 上游仍是 12.7.0，SDK 缓存层的 ZodError 未修 |
| 投票生命周期（clarify） | 保留，重新实现 | 上游没有多选和关闭后隔离 |
| 语音文件名 `.m4a` | 保留 | 上游没有 |
| cron `execution_id` | 保留 | `ollo-inbox` 去重需要；上游没有 |
| Ollo 插件 | 保留 | Ollo 网关分步接管前还要用 |

sidecar 随之回到上游的 `spectrum-ts 12.7.0` 和上游 `package-lock.json`。

## 变基（Codex）

`main` 快进到 `v0.21.6`，`custom` 用只含 7 个 pick 的 todo 变基，另加两个提交。Codex 的 `workspace-write` 沙箱默认禁止写 `.git`，第一次因此没能开始；之后只给开发副本的 `.git` 开放写权限（`~/.hermes` 仍不可写）完成。

| 冲突 | 处理 |
| --- | --- |
| `plugins/platforms/photon/adapter.py`（生命周期补丁） | 原实现建立在已移除的回执补丁上。以 v0.21.6 适配器为底重写：只登记 `send_clarify` 成功发出且有消息 ID 的投票；从 Spectrum 投票事件 ID（`<投票消息 GUID>:<发送者>:<选项>:<动作>:<时间>`，12.7.0 已核对）取父投票；单选首次有效选择直接解除等待，之后的变更静默吸收；多选按发送者收集，「✅ 完成选择」一次提交；其他投票完全走上游逻辑 |
| `tests/plugins/platforms/photon/test_poll_clarify.py` | 保留上游用例，迁入旧用例 |
| `plugins/platforms/photon/sidecar/index.mjs`（语音补丁） | 导入区夹带已移除的位置、mini-app、旧 reply 导入，只保留 `normalizeVoiceAttachmentName` |
| `.gitignore`（插件迁移提交） | 保留上游新增的规则，再追加插件规则 |

行为变化：旧版会静默丢弃「无法关联的投票」（例如重启前发出的 clarify 投票上的后续点选）；现在这类投票按上游语义当作文字转给网关。

新增提交：`chore(plugins): drop stale hermes-plus gitignore exceptions`；`test(plugins): follow v0.21.6 run stream in ollo-conversation mood test`（v0.21.6 的终止事件经 `loop.call_soon` 进入 `_RunStream`，测试要先让出事件循环再读）。sidecar 的 `npm test` 补上语音文件名测试，并入语音补丁提交。

`range-diff`：12 个 `<`（移除）、4 个 `=`、3 个 `!`（生命周期重写；语音补丁的导入上下文与测试脚本；插件迁移提交的 `.gitignore` 上下文）、2 个 `>`（新增）。

## 测试

环境：开发副本按 [维护方式](../maintenance.md#开发环境) 用隔离的 `HERMES_RUNTIME_DIR`、`HERMES_HOME` 装 pm 环境（Python 3.14.7、node 26.7.0），确认没有创建 `~/.hermes/tools`。

| 范围 | 结果 |
| --- | --- |
| sidecar `npm test`（空标题 3、语音文件名 1） | 4 passed；空标题补丁确认打到 `@spectrum-ts/imessage` 12.7.0 |
| Photon 全目录 + `tests/cron/` + `test_session_info.py` + `hermes-plugins/` | 186 个文件，1,746 passed、1 failed、12 skipped → 修正语气测试后插件与投票 9 个文件 121 项全过 |
| 全量 `scripts/run_tests.sh -j 8` | 5,463 个文件，58,278 passed、172 failed、1,416 skipped，2,140.7 秒；3 个文件首次失败、重试通过（`test_update_interrupted_pull.py`、`test_file_operations.py`、`test_search_auto_multiline.py`）；失败分布在 62 个文件，没有一个在 Photon、`hermes-plugins/`、`tests/cron/` |
| 62 个失败文件在纯官方 v0.21.6 副本复跑 | 1,490 passed、168 failed、62 skipped。按测试标识比较：166 项共同失败；custom 单侧 11 项，全部在搜索与文件操作测试（`ProcessLookupError` 竞态），这 5 个文件与官方逐字节相同，在 custom 上单 worker 复跑 129 passed、0 failed；官方单侧 2 项（`test_local_models_routes.py` 的下载续传） |

结论：没有发现可复现的 custom 新增回归。全量不是全绿；共同失败集中在更新器与 launchd、SQLite 维护与修复、pm 下载、桌面与多 profile、可选 provider 等，与本 fork 的补丁无关。

语言覆盖：在隔离的 `HERMES_HOME` 放入 `locales/zh.yaml`、`en.yaml` 后，`t("gateway.session.auto_reset_notice")` 返回新文案，其他键不变；去掉覆盖则恢复上游文案。
