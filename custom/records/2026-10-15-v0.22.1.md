## 发行版

v0.21.6 之后官方发了三个正式版：[v0.21.7](https://github.com/NousResearch/hermes-agent/releases/tag/v0.21.7)（10-12）、[v0.22.0](https://github.com/NousResearch/hermes-agent/releases/tag/v0.22.0)（10-14）、[v0.22.1](https://github.com/NousResearch/hermes-agent/releases/tag/v0.22.1)（北京时间 10-15 07:59）。三者依次包含，都能从 `upstream/main` 到达，`main` 是它们的祖先。v0.22.1 名为补丁版，但比 v0.22.0 多 2,216 个提交，大量改动在 cron 投递和 `/v1/runs`。目标定为 v0.22.1。

和本 fork 相关的变化：

- **API run 走会话权威**：常驻网关有 `session_authority` 时，`POST /v1/runs` 先持久接收（admission），再由 canonical turn 执行；API server 不再为这类 run 创建 agent 对象。这是部署前阻断的来源。
- **cron 投递**：普通 agent cron 在发送前按执行 ID 持久入队，新增终态回写与对账（`cron/delivery_outcome.py`）、durable delivery 与重复告警防护。
- **一台机器默认只跑一个网关**：`hermes update` 会把各档案的网关并到一个；有冲突时不合并。本机 default 与 care 共用过 Photon 凭据，现在 Photon 已关，部署时要看更新器怎么处理。
- **会话自动清理**：发行说明列为默认开启（ended 且 90 天未活动）。核对发现 v0.21.6 的默认值已经是开启，详见下文。
- **其他**：`session_reset` 定时重置正式退役（本机已删配置）；插件旧兼容导入层移除（Ollo 插件引用的模块和名字都还在）；部分工具改名，旧名仍可用；source 安装的更新器默认跟随正式版，fork 仍跟随分支；launchd 任务的处理有改动，部署后要核对 LaunchAgent 是否仍经 `osascript` 启动。

## 部署前的阻断：ollo-bridge 的确认身份

插件测试全过，但覆盖不到线上路径。读代码确认：

- v0.22.1 `gateway/platforms/api_server_runs.py` 822–827：网关有 `session_authority` 时，`/v1/runs` 先经 `_admit_run_to_authority`，`run.admission` 有值；1042–1068 的 admission 分支只观察 canonical turn，不创建 agent、不写 `_active_run_agents[run_id]`；只有 1069–1077 的旧分支才这样做。新执行器把 approval ContextVar 设为会话键（`gateway/run_turn_runner.py` 886–899），不再是 run_id。
- `hermes-plugins/ollo-bridge/identity.py` 的 `current_run_id()` 依赖「approval ContextVar = run_id」和 `_active_run_agents`，在线上会返回 None，`execute_gtd_confirmation` 等确认操作将一律 403。不能直接拿会话键代替 run_id，否则会破坏授权身份的约定。
- 测试夹具（`hermes-plugins/conftest.py`）没有构建会话权威，走的都是旧分支，所以测试全过。

Codex 还列了几项可能的行为变化：Idempotency-Key 与 run 的绑定时序、`_ensure_session_db` 在有 runner 时改取 authority store、`cron.jobs.mark_job_run` 新增 `execution_id` 并按 canonical completions 去重、`auxiliary_client` 的异步校验移到线程。由设计会话在新基线上适配插件，并补一条走真实会话权威的集成测试；适配通过前运行目录保持 v0.21.6。
